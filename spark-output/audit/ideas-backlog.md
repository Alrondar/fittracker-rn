# Ideas backlog — FitTracker RN (сверх аудита UX-1…UX-4)

Срез: 25.09.2026. Результат брейншторма «за рамками md-документов», сверенный с кодом.
Статусы: ✅ согласовано · ❓ на обсуждении · ❌ отклонено (уже есть / не подходит).

## ✅ Согласованные идеи

### I-1. Движущиеся числа (count-up)
- Все ключевые числа (Progress hero, WeeklyStats, Dashboard-статы) — анимация роста 0→value ~600ms ease-out при появлении.
- SVG-графики — прорисовка stroke-dashoffset при первом входе в viewport.
- Стек: уже есть (Reanimated + react-native-svg). Риск: низкий.

### I-2. Язык хаптиков (и звуков)
- Единая хореография: выбор/завершение сета = light/medium, конец отдыха = двойной тик + bell, PR = success-pattern.
- expo-audio уже в зависимостях — проверить, не используется ли только для техники упражнений.
- Требует: константный файл haptic-patterns (типизировать), не размазывать вызовы инлайном.

### I-3. Полировка RestTimer (НЕ переделка!)
- Факт: RestTimer v2 уже содержит кольцо, цветовые фазы 30/10с, пульс 3с, vibrate-until-dismissed, pill-режим.
- Осталось: (а) градиентный stroke кольца из colors.gradients; (б) тикающий haptic в последние 3с; (в) вспышка кольца + success-haptic в момент «Отдых окончен».
- Объём: ~1 час. Полноэкранный редизайн — ОТКЛОНИН, дублирует существующее.

### I-4. Hero-морфинг «Сегодня → тренировка»
- Dashboard: «тренировка дня» вынести в крупный hero-блок; тап морфит карточку в экран workout (shared-element / slide+scale).
- Один жест закрывает путь «открыл приложение → начал тренировку».
- Связан с UX-1 (stackAnimation) — делать в одном пакете.

### I-5. PR-момент без конфетти
- Новый рекорд: glow/обводка карточки цветом primary, бейдж с весом, scale-pop числа, success-haptic. Никаких частиц.
- Точка врезки: экран workout при завершении подхода (PersonalRecordsCard как secondary-поверхность).

### I-8. Тема как личность (онбординг)
- Выбор акцента с live-preview: тап по акценту перекрашивает фоновый превью-экран cross-fade.
- Опционально: «gym mode» — авто-dark на экране тренировки (обсудить отдельно).

### I-6. Жесты (пересмотрено 25.09 после замечания пользователя)
- **I-6a**: long-press заголовка упражнения → превью альтернатив (AlternativeExerciseCard уже есть). Нулевой риск. Ждёт решения, включать ли в UX-1.
- **I-6c (отложено)**: кастомный pull-to-refresh со «штангой» вместо системного спиннера.
- Итог ревизии: жестовый слой приложения в основном уже закрыт — drag-reorder в редакторе программ (react-native-draggable-flatlist), swipe-downdismiss у SheetShell, pull-to-refresh на 4 из 5 tabs. Новые жесты вводить только под реальную задачу, не «для красоты».

## ❌ Отклонено

### I-6b. Swipe-завершение подхода — ОТКЛОНИНО (25.09)
- Подход завершается самим фактом ввода веса/повторов/RPE (и авто-старт отдыха привязан к completedSets в SetsGrid). Свайп-галочка = дубль существующей семантики + риск ложных завершений в зале. Решение пользователя.

### I-7. Тепловая карта мышц — УЖЕ РЕАЛИЗОВАНО
- MuscleStatsSection: вкладки Нагрузка/Усталость/Сила + периоды 7/30/90/Всё, MuscleLoadMap/BodyMap, тема-зависимые цвета.
- **Одобрено (25.09)**: анимированный cross-fade перекраски карты при смене вкладки/периода (~50 строк, useAnimatedProps на fill).
- **Найдено пользователем (25.09)**: кнопки «Все/Прямые» (MuscleLoadModeToggle) в ~1.5 раза меньше соседнего фильтра периодов (PillToggle) и нарушают tap target ≥44px → зафиксировано как finding audit-14 (см. fittracker-rn.md); фикс = заменить на PillToggle с тем же API или выровнять масштаб.
