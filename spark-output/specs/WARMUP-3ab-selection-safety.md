# WARMUP-3ab — безопасный и честный подбор разминки

Пакет 1 трека WARMUP-3 (объединил 3a безопасность + 3b движок по решению владельца, 08.10).
Сопутствующие решения владельца: компоновка L1 «текущее + очередь» → отдельный пакет 3c;
настройка порядка разминки → вынести в настройки как пресет; разминочные подходы (ramp-up) → отдельный пакет 3d.

## 0. Владение фактами

- Продуктовый intent и дизайн-скилл — `PRODUCT.md §3.1–3.5` (здесь только применяются, не дублируются).
- Технические gates — `CLAUDE.md §8/§14` (здесь только ссылки).
- Статус/метрики после реализации — `STATUS.md` (секция WARMUP), роли/blast-radius — `INVENTORY.md`.
- Спецификация протокола ramp-up остаётся в `STATUS.md:315` (ENG-12), сюда не переносится.

## 1. User goal

Человек открывает тренировку, видит блок «Разминка» и за 1–2 действия понимает: это подобрано
под *сегодняшний* день, это безопасно при его травмах, это занимает правдоподобное время,
и кнопка ⟳ действительно даёт другой набор.

Критерий успеха (что проверяем, а не «стало лучше»):

| # | Утверждение | Как проверяется |
|---|---|---|
| G1 | Ни одно упражнение из разминки и её вариантов не противопоказано активным травмам без явного подтверждения | код + тест-хarness (см. §7, случай S-1) |
| G2 | Скоринг видит весь пул, а не 80 из 178 | diff запроса + лог числа кандидатов в harness |
| G3 | Каждая крупная группа дня покрыта ≥1 упражнением разминки | harness: 20 реальных дней, `uncoveredGroups = 0` |
| G4 | ⟳ даёт другой набор, а в рамках одного захода набор стабилен | harness: seed-детерминизм + regen-отличие |
| G5 | «~N мин» соответствует реальной сумме длительностей и лежит в 6–12 мин | harness: сумма `duration_seconds` |
| G6 | Разминка не дублирует упражнение, которое и так стоит в дне | harness: `selected ∩ day.exerciseIds = ∅` |

## 2. Что вне объёма этого пакета

- Компоновка блока (L1 «текущее + очередь»), resume/unmark, 44 px, автопереход на вкладку → **WARMUP-3c**.
- Разминочные подходы с нарастающим весом (`is_warmup` в сетах) → **WARMUP-3d**.
- Любые DDL/прод-миграции, новая колонка `exercises.warmup_seconds`, персистентность выполнения разминки → вне трека, отдельное решение.
- `relevance_score` в UI не показываем (нет запроса на «почему именно это» в этом пакете).

## 3. Модель данных, на которую опираемся (проверено продом 08.10)

Пул разминки (`category = 'stretching' OR can_be_activation`) = **178** строк: 104 растяжка, 94 активация.

| Bucket | Условие | Строк | Назначение |
|---|---|---:|---|
| `general` | `movement_pattern ∈ {gait, jump, step_up}` | 9 | разогрев (тонко, используем как опциональный первый шаг) |
| `activation` | `can_be_activation = true` | 94 | активация целевых мышц |
| `mobility` | `stretching AND NOT activation AND movement_pattern NOT NULL` | 15 | динамическая мобилити |
| `static` | `stretching AND NOT activation AND movement_pattern IS NULL` | 69 | статическая растяжка / МФР |

Прочие проверенные факты:

- `status`: в пуле 88 `approved` и 90 `needs_review` — фильтр «только approved» роняет покрытие худшего реального дня с 26 до 10 кандидатов (активация 7 / растяжка 3) → **два яруса, не жёсткий фильтр**.
- `movement_pattern` заполнен у 100/178; vocabulary: rotation 21, hinge 8, gait 6, squat 4, lunge 4, wrist_forearm 4, shoulder_raise 4, push_vertical 8, pull_horizontal 7 и т.д. → годен как сигнал покрытия.
- `difficulty` заполнен у 178/178 (почти всё `beginner`), `aliases` — у 163/178, `reps_range` — у **0/178**.
- **Длительности в БД нет**: `settings` — текст про оборудование, совпадений с `(\d+)\s*(сек|с)` 0/178 → сегодня каждый пункт = 30 с, весь блок = 3,5 мин, чип «~4 мин» константа.
- Строгое равенство по мышцам не покрывает 4 группы из программ: `нижняя часть большой грудной` (50 использований), `камбаловидная` (40), `брахиорадиалис` (19), `нижняя часть прямой мышцы живота` (8) → 0 пересечений с пулом.

## 4. Спецификация подбора (WARMUP-3b)

### 4.1 Архитектура

Новый чистый модуль `src/engine/warmupPlan.ts` (паттерн `engine/alternatives.ts`: без React, без Supabase, детерминирован).
`src/services/warmupService.ts` остаётся оркестратором запросов: получает кандидатов → отдаёт в `planWarmup()` → догружает тяжёлые поля.
Никаких новых экранов/компонентов в этом пакете.

```ts
planWarmup(input: WarmupPlanInput): WarmupPlanResult

WarmupPlanInput {
  dayMuscles: Record<string, number>        // primary +2 / secondary +1, lowercased
  dayPatterns: string[]                     // movement_pattern основных упражнений дня
  dayEquipment: string[]                    // для strengthFocused
  dayExerciseIds: string[]                  // чтобы не дублировать день (G6)
  candidates: WarmupCandidateLight[]        // весь пул, без limit
  activeInjuries: UserInjury[]
  contraindications: Record<string, Contra[]>
  order: WarmupOrder                         // см. §6
  seed: string                               // userId|workoutId|regenCounter
  targetCount?: number                       // по умолчанию динамический
}
WarmupPlanResult { selected; uncoveredGroups; excludedByInjury; totalSeconds }
```

### 4.2 Запрос кандидатов

- Убрать `.limit(80)`; добавить `.order('name')` — результат не должен зависеть от физического порядка страниц (после `VACUUM` разминка сейчас молча меняется).
- Формулировка: `select(WARMUP_LIGHT_FIELDS + ', movement_pattern, difficulty, aliases, status')`, `.or(WARMUP_POOL_OR)`, `.order('name')`. Объём: 178 × ~7 коротких полей ≈ 30–40 КБ — один запрос вместо двух сетевых раундов, которые мы всё равно делаем сейчас (light + heavy).
- Тяжёлые поля (`technique/benefits/risks/media_url`) — как и сейчас, только для финальных (PERF-3 не регрессирует).
- Ярусы статуса: `approved` приоритетом; `needs_review` допускается только добором, если ярус 1 не закрыл `targetCount`.

### 4.3 Скоринг

```
score = muscleContribution                       // как сейчас: primary 2 / secondary 1
      + patternBonus        (+3 если movement_pattern дня ∈ паттернов кандидата)
      + bucketBonus         (+2 activation при strengthFocused; +1 mobility)
      + machineBonus        (+3, тренажёр в силовой день — переносим как есть)
      − injuryPenalty       (два уровня, переносим как есть: contra/high → exclude, medium −5, low −2)
      − diversityPenalty    (−4 за каждый следующий кандидат с той же доминирующей primary-мышцей)
      − duplicateDayPenalty (−∞ если id ∈ dayExerciseIds)  // G6
      − advancedPenalty     (−3 если difficulty='advanced' и профиль beginner)
```

`strengthFocused`/`MACHINE_KEYWORDS` переезжают в `warmupPlan.ts` без изменения списков ключевых слов
(иначе поедут известные результаты; расширение словаря — вне пакета).

### 4.4 Правило покрытия (главное изменение качества)

До «взять топ-N»: для каждой из top-3 грузимых мышц дня (по `dayMuscles`) и для каждого паттерна дня
(≤4, по убыванию веса) гарантированно выбирается 1 не противопоказанный кандидат с максимальным счётом,
покрывающий этот слот. Остальные слоты — добор по счёту. При конфликте (слот нечем закрыть) —
не выдумываем: слот пропускается, `uncoveredGroups` растёт, harness это показывает.

### 4.5 Нормализация мышц

`src/engine/warmupPlan.ts::expandMuscleKey()` — статическая карта групп + `aliases` кандидата:

```
низ груди      → нижняя часть большой грудной, большая грудная, передняя дельта
икры           → камбаловидная, икроножная
предплечья     → брахиорадиалис, мышцы предплечья, разгибатели предплечья
низ живота     → нижняя часть прямой мышцы живота, прямая мышца живота, поперечная мышца живота
плечи          → передняя/средняя/задняя дельта, дельтовидные, трапеция, ротаторная манжета
```

Влияет только на скоринг (совпадение «мышца дня → кандидат»), исходные метки в UI не подменяются.

### 4.6 Размер и состав

`targetCount = clamp(5, 4 + ceil(nDayExercises / 3), 8)`; `strengthFocused` и наличие squat/hinge/lunge
добавляют +1 (потолок 8). Баланс: `static ≤ 2`, `activation ≤ 3` — иначе не остаётся места под мобилити.
Пустой пул/нехватка → возвращаем сколько есть (не добираем контра-упражнениями).

### 4.7 Длительности (G5)

`warmupDurationSeconds(bucket, movementPattern, difficulty)`:

| Bucket | Сек | Комментарий |
|---|---:|---|
| `general` (gait/jump/step_up) | 60 | разогрев |
| `activation` | 45 | резинка/тренажёр, 1–2 подхода лёгкие |
| `mobility` | 40 | динамическая, по сторонам |
| `static` | 30 | удержание |

×2 для упражнений с маркером двусторонности в имени (право/лево, «поочерёдно») — если такой маркер есть в `name`/`aliases`; сверить при реализации, не выдумывать.
`parseWarmupDuration` остаётся как приоритет: если в `settings` вдруг появятся секунды — они выигрывают.
Чип «~N мин» в `WarmupBlock` больше не правим — он уже берёт `totalDuration` из хука, и он станет честным сам.

### 4.8 Сид и рандомизация (G4)

Взвешенная выборка без возвращения из топ-`min(12, N)` по счёту, ГПСЧ mulberry32 от хэша `seed`.
`seed = userId|workoutId|regenCounter`; `regenCounter` инкрементируется в `useWarmup` по тапу ⟳ и сбрасывается при смене мышц/травм/порядка.
Сортировка внутри результата — по бакету и порядку (§6), а не по счёту, чтобы вид не «прыгал» между перегенерациями.

## 5. Безопасность (WARMUP-3a)

### 5.1 Варианты замены в листе

`getWarmupAlternatives(exerciseId, primaryMuscles, activeInjuries)` — добавить третий параметр и прогнать
собранных кандидатов через существующий `rankAlternatives()` (`engine/alternatives.ts`), тот возвращает
`excludedCount`. Дублирования двухуровневой логики не заводим (правило владения).
Вызовы: `useWarmup.loadWarmupAlternatives` (передаёт `activeInjuries` из замыкания хука), кэш — по `id + injuryKey`,
иначе список залипает после изменения травмы.

### 5.2 Ручная замена

`replaceWarmupExercise` перед применением проверяет кандидата через тот же уровень 1/2:
про contra-indicated — `feedback.alert` «Это упражнение противопоказано при твоей травме (Плечо).
Всё равно заменить?» с вариантами «Отмена» / «Всё равно заменить» (destructive), паттерн подтверждения как в UX-5.
При «Всё равно» — применяем локально, **но предпочтение в `warmup_preferences` не пишем**
(иначе contraindicated-вариант станет нормой для всех будущих разминок).

### 5.3 Чип про травмы

Сегодня `Учтены травмы: Плечо (−3)` считает отброшенных *кандидатов*, пользователь не видит ничего полезного.
Меняем смысл на наблюдаемый: `excludedByInjury` → по числу *скрытых упражнений* по зоне, и рядом подпись
`N скрыто из-за травм` в листе вариантов — ровно как в основных карточках.
Без нового компонента: существующий чип + `numberOfLines={2}`; список «что именно» → в 3c вместе с L2-листкой чипа.

## 6. Настройка порядка (решение владельца: пресет в настройках)

Флаг `activationFirst: boolean` → `warmupOrder` enum в `useTimerSettings`:

| Значение | Подпись в UI | Порядок бакетов |
|---|---|---|
| `graded` (дефолт для новых) | «По порядку: разогрев → активация → подвижность → растяжка» | general, activation, mobility, static |
| `activation_first` | «Сначала активация, потом растяжка» | activation, mobility, static |
| `stretch_first` (текущий дефолт) | «Сначала растяжка» | static, mobility, activation |

Миграция: при чтении AsyncStorage `activationFirst === false → stretch_first`, `true → activation_first`.
**Поведение существующего пользователя не меняется молча** — он получает свою прежнюю пару в новой обёртке;
`graded` выбирается вручную или при первой установке. Носитель UI — `src/components/settings/RestTimerSection.tsx:53-58`
(там же, где был тумблер), тип контрола — `PillToggle`/`SheetShell`-picker по §3.6, без нового компонента.
Хук `useWarmup` уже реагирует на изменение (deps `activationFirst`) — заменить на `warmupOrder`.

## 8. Acceptance criteria

- Given травма «плечо, medium» и открытая шторка вариантов разминки, When смотрю список, Then контра-упражнения отсутствуют, а счётчик «N скрыто из-за травм» показывает, что фильтрация была.
- Given травма «плечо, high», When настаиваю на contraindicated-замене, Then получаю подтверждение; если подтвердил — замена действует только на эту тренировку, в `warmup_preferences` не пишется.
- Given день на 6 упражнений, When открываю разминку, Then кандидатов для скоринга 178 (не 80), а суммарная длительность попадает в 6–12 мин и равна сумме показанных секунд.
- Given одна и та же тренировка, When тапаю ⟳ трижды, Then каждый раз получаю другой набор, а при возврате и повторном открытии экрана в рамках сессии набор не «прыгает».
- Given приседания в дне, When смотрю разминку, Then хотя бы один пункт покрывает тазобедренные/голеностопные паттерны (squat/hinge), и ни один пункт не повторяет упражнение из самого дня.
- Given существующий пользователь с `activationFirst=false`, When обновляет приложение, Then у него выбрано «Сначала растяжка» (прежнее поведение), а не новая рекомендация.

## 9. Нужны решения владельца

1. **Дефолт порядка.** Предлагаю: существующим — сохранить прежнее поведение, `graded` только для новых установок. Если хочешь перевести всех на рекомендуемый порядок — скажи, это осознанная смена поведения.
2. **`needs_review` как добор.** Оставляем (иначе худшие дни падают до 10 кандидатов и состав ломается), но можно и жёстко резать по `approved` с миролой «разминка короче, если нечего подобрать».
3. **Размер блока.** 5–8 пунктов (предложение) против нынешних 7 — подтверди, что динамический размер ок, потому что от него зависит и высота блока в 3c.

## 11. Реализовано 08.10 — зафиксированные отклонения

Пакет закрыт (STATUS §15.2). Три пункта спеки уточнены по данным, обнаруженным при реализации:

1. **§4.7 правило «×2 для двусторонних» отменено.** Маркеров «поочерёдно / право / лево / каждой стороны» в `name` и `aliases` пула — 0 строк (проверено SQL). Выдумывать флаг не стали. Итоговые длительности: `general 120 / activation 60 / mobility 45 / static 40` (в спеке были 60/45/40/30 — с ними блок выходил 4–5 мин, что не проходит G5).
2. **§5.2 confirm-алерт на противопоказанную замену не нужен.** `getWarmupAlternatives` отсекает контра-варианты до того, как они попадут в список (общий `rankAlternatives`), поэтому «всё равно заменить» было бы недостижимым кодом. Поведение совпадает с заменами основных упражнений: не подтверждаем, а скрываем + «N скрыто из-за травм». Запрет на запись в `warmup_preferences` остаётся на уровне `isPrefAllowedForInjuries` при подстановке.
3. **§4.4 паттерные слоты — best-effort, мышечные — жёсткие.** При потолках состава (activation ≤3, static ≤2, general ≤1) 55 из 160 паттерных слотов по 40 дням остаются незакрытыми; в harness это INFO-строка, провалом считается только непокрытая мышца.
