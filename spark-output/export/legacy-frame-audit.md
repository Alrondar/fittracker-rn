## Методика и границы доказательности

Три слоя, от самого надёжного к оценочному.

1. **Ссылочный (полный охват, 778/778).** Имя папки в `media_url` сравнивается с `name_eng`
   строки после нормализации пунктуации (`/`, скобки, апостроф, дефисы, «е/ё»). Работает,
   потому что кадр легаси-строки всегда изображает ровно ту запись датасета, в чьей папке лежит,
   а `name_eng` — это и есть имя записи. Дало **40** строк с чужой ссылкой на 12.10, **34** на 14.10.
2. **Семантический (полный охват найденного, 40/40).** Каждая из 40 строк открыта глазами вместе
   с кадром по её ссылке; у 22 дополнительно проверено, есть ли в датасете запись с собственным
   именем строки (`data/exercises/<name_eng>.json`). Делило 40 на «кадр про другое движение» (19)

   чужой папке: 11 из «кадр про другое движение» (шесть закрыты) и 23 класса B.
3. **Текстовый (выборка, 12/738).** Наши `technique` — не перевод карточки датасета, а
   самостоятельный текст, поэтому расхождение уровня деталей возможно и там, где ссылка верна.
   Случайная выборка 12 строк: 1 прямое противоречие по позе, 1 спорная, 10 совпадают.

### Две строки сняты: моя ошибка просмотра

`a4e1a02f` «Пуловер со штангой на спину» и `668309c4` «Жим гантелей лежа обратным хватом»
переведены в класс B. Я читал их с контактного листа, где каждый кадр уменьшен до 420 px,
и не разобрал ни снаряд, ни направление движения. В полном размере: на кадре пуловера
**штанга** (один гриф с блинами в двух руках), уходит по дуге за голову со слегка согнутыми

снаряд / другое движение» держится только если оно не противоречит имени самой записи-источника.

## Почему так вышло

Каталог импортирован из `free-exercise-db`, и `media_url` подвешивался по похожести названия, а не
по соответствию движению: у 21 строки из 22 разобранных вручную **собственной карточки в датасете
нет вообще** (проверено по `data/exercises/*.json`) — то есть строка изначально заводилась под чужой
кадр. Дедупликация 09.10 (842 → 825) эти ссылки не чинила: она сливала дубли по имени, а её шаг
`set name_eng = coalesce(k.name_eng, d.name_eng), media_url = coalesce(k.media_url, d.media_url)`
переносил чужой кадр на оставляемую строку, если у своей кадра не было, — то есть часть расхождений
закрепляла. Находка была зафиксирована раньше этого аудита как открытые вердикты `ILL-Q2`
(28 позиций с одолженным кадром) и `ILL-Q3` (4 позиции, где имя свободно, но движение другое) —
`STATUS.md`, строки 173–174.

## Что важно помнить при правках

* Битых ссылок нет ни в легаси, ни у нас: **772** легаси-строки ведут на апстрим-репозиторий,
  который мы не трогаем, **49** наших — на `Alrondar/fittracker-rn`, и все 49 входных URL
  проверены 14.10 (43 старых + 6 новых, каждый отдал 200). Удаление `0.jpg`/`1.jpg` из наших
  папок на них не влияет.
* Переключать строку на `00f.jpg` можно только когда в папке лежат **обе** пары (`00f/01f` и
  `00m/01m`): на уровне кода наличие мужской пары неотличимо от наличия женской, оба имени
  вычисляются из одного префикса, и без второй пары профиль «мужчина» упирается в 404.
  Механический проверщик — `spark-output/export/check-media-names.py`.
* Имя папки выводится из `name_eng` дословно, включая дефисы: у «Журавлика» написание
  `Crane_Single_Leg_Glute_Hinge` отдавало 404, а `Crane_Single-Leg_Glute_Hinge` — 200
  (переименование `0056dce`). Перед миграцией всегда проверять curl'ом, а не по памяти.
* Клиент читает только `media_url` (`src/utils/mediaScheme.ts`), поэтому для смены кадра в
  приложении и на вебе не нужна правка кода — но кеш `src/lib/queryPersistence.ts` держит
  старый ответ, нужен свежий прогон.
* `program_exercises.exercise_name` хранит снимок русского имени — правка `technique`, `name_eng`
  или `media_url` уже созданные тренировки не меняет.
* `name_eng` в UI не рендерится, но его матчит `search_exercises` и из него выводится имя папки,
  поэтому оставлять ошибочное имя нельзя.
* Механический проверщик (регэксп по имени папки) не заменяет этот реестр: он продолжает считать
  расхождением строки класса B, где кадр верный. На 14.10 он даёт **34** — это 11 остатка
  класса A плюс 23 класса B, а не 34 дефекта.

## Как перепроверить

```sql
-- счётчик строк со ссылкой на другую запись: 41 на 11.10, 40 после 12.10, 34 после 14.10
with t as (select split_part(split_part(media_url,'/exercises/',2),'/',1) f,
                  replace(name_eng,' ','_') e from exercises where media_url like '%/0.jpg'),
n as (select regexp_replace(translate(lower(f),'ёе/()''-,.','ee_____'),'[^a-z0-9]','','g') f,
             regexp_replace(translate(lower(e),'ёе/()''-,.','ee_____'),'[^a-z0-9]','','g') e from t)
select count(*) filter (where f<>e) chuzhaya_ssylka, count(*) total from n;

-- откуда берётся кадр (14.10): our_host 49, upstream 772, no_media 5, total 826,
-- ours_not_new_scheme 0 — то есть все наши ссылки ведут на 00f.jpg новой схемы
select count(*) filter (where media_url like '%Alrondar/fittracker-rn%') our_host,
       count(*) filter (where media_url like '%free-exercise-db%')        upstream,
       count(*) filter (where media_url is null)                          no_media,
       count(*)                                                           total,
       count(*) filter (where media_url like '%Alrondar%'
                             and media_url not like '%/00f.jpg')          ours_not_new_scheme
  from exercises;

-- занятость строк класса A перед каждой партией (cat — каталожные программы, hist — история)
with ids(p) as (values ('216243c9'),('026fe9a4'),('a8a977d2'),('cb22b47b'),('4e36cf74'),
                      ('5f214a11'),('f24044ec'),('c557b192'),('9a77e5f5'),('10a3fed1'),('e4bcc6ac')),
e as (select x.id, x.name, x.status,
             split_part(split_part(x.media_url,'/exercises/',2),'/',1) as folder
        from exercises x join ids i on x.id::text like i.p||'%')
select e.name, e.folder, e.status,
       coalesce((select count(*) from program_exercises pe
                   join program_days pd on pd.id = pe.program_day_id
                   join programs pr on pr.id = pd.program_id
                  where pe.exercise_id = e.id and pr.created_by is null), 0) as cat,
       coalesce((select count(*) from workout_exercises we
                  where we.exercise_id = e.id), 0) as hist
  from e order by hist desc, cat desc;

-- коллизии name_eng
select name_eng, count(*) from exercises where name_eng is not null group by 1 having count(*)>1;

-- папки, общие у двух строк (14.10: 11)
select split_part(split_part(media_url,'/exercises/',2),'/',1) f, count(*)
  from exercises where media_url like '%/0.jpg' group by 1 having count(*)>1;
```
