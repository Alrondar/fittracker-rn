## 2. Методология

Что считается показателем выполнения:

| Термин | Как считалось |
|---|---|
| Выполненная тренировка | `workouts.started_at IS NOT NULL AND skipped_at IS NULL` |
| План подходов | снапшот `workout_exercises.sets` (то, что было в конкретной тренировке) |
| Рабочий подход | `workout_logs` c `is_warmup = false` |
| Приверженность, % | рабочие подходы / план подходов в этой тренировке |
| Top set | максимальный `weight_kg` в сессии по упражнению и повторы в этом подходе |
| e1RM | формула Эпли: `weight × (1 + reps / 30)` — оценка, не замер |
| Тоннаж | Σ(`weight_kg` × `reps`) по рабочим подходам |
| Недельный объём по мышцам | `unnest(exercises.primary_muscles)` × выполненные рабочие подходы |

Ограничения: подходы размечены как `is_warmup = false` во всех 298 логах (разминка не размечена вообще) → реальный объём может быть выше учтённого; `weight_kg = 0` у подтягиваний (собственный вес не учитывается) → их тоннаж = 0; в `is_estimated_reps` ни один лог не помечен.

## 11. Выводы анализа

1. **5-дневная структура не выполняется.** Полноценно закрыты только 4 недели из 5 дней: Legs пропущен 2 из 3, Hybrid «сдут» в 1 подход в wk2. Это не лень, а структура: дни идут Push→Pull→Legs→Upper→Hybrid, и ноги стоят между двумя лучшими для пользователя днями.
2. **Объём ног ≈ 0.** Рабочие подходы на квадрицепс/заднюю поверхность/ягодицы: 0 / 18 / 0 при трёх неделях наблюдения. Присед, румынка, жим ногами имеют ровно по одной сессии — прогрессия по ним не может существовать. Икр в фазе 1 программы нет вообще.
3. **Дисбаланс тяг.** 5 тяговых упражнений на спину в неделю (блок V-рукоять, блок широкий хват, блок одной рукой, пуловер, рычажная изометрия) при фактических 19–25 подходах — верхняя граница «много», и при этом перевыполнение: в wk3 25 из 21 плановых. При такой приверженности тяги «съедают» объём, который должен идти ногам.
4. **Жим лежа: план ломает прогресс.** `progression_policy = linear` + коридор 6-10 + target RPE 8, а факт: 95×6 → 110×8 → 100×7 → 90×6 и RIR 2.4 (то есть RPE ≈ 7.6, запас до отказа больше цели). Линейная прогрессия здесь не работает: пользователь сам «гуляет» по весу на 15-20 кг, и e1RM откатился на −22%.
5. **Плечо — красный флаг.** Две стартовые жалобы на боль (OHP, махи перед собой), а программа даёт: OHP в Push + OHP-подобный жим гантелей сидя в Upper + махи перед собой 3 подхода + тяга к подбородку узким хватом 4 подхода. Это самый вероятный источник future-проблем, и именно махи перед собой он стабильно недоделывает (75% приверженность, RIR 2.2 при target 9).
6. **Изоляция в конце дня — «отвальные хвосты».** Все провалы приверженности сосредоточены в изоляции: бицепс на Pull wk2 (3 упражнения → 0 подходов), обратные разведения (0 в wk2), махи в наклоне (67%), тяга одной рукой (67%), жим гантелей на Hybrid (50%). Их 25+ плановых подходов в неделю, которые пользователь систематически не делает, — то есть программа перегружена «хвостами», а не ключевыми движениями.
7. **Интенсивность рассогласована с целью.** Средний RIR 2.1 при target RPE 8 (RIR ≈ 2) в целом ок, но разброс велик: пуловер/V-тяга RIR 1.3–1.4 (слишком близко к отказу для подсобки на 12-15 повторов), тогда как жим лежа/махи RIR 2.2–2.4 (слишком легко). Одна и та же «средняя» цель RPE 8-9 не работает между базой и изоляцией.
8. **Фаза 2 («Сила») по текущему поведению обречена.** Она требует 5×4-6 со становой и приседом и 180 с отдыха, на фоне того, что (а) ноги и так пропускаются, (б) свободновесовой жим уже откатывается, (в) плечо болит. Переход в фазу 2 на wk5 без структурных правок почти наверняка даст ещё больше пропусков.
9. **Структурный дефект самой программы:** день 5 = Hybrid в фазе 1 и Lower в фазах 2-3 (`program_days` фаз различаются по составу дня 5). Цикл «PPLUL» позиционируется как PPL + Upper/Lower, фактически же в единственной выполняемой фазе ног один, а в дилоуде — два.
10. **Когда ноги всё-таки делаются, они дают максимальный объём:** тоннаж ножной недели wk2 — 15 002 кг, больше тоннажа любого верхнего дня за ту же неделю. Это аргумент не «убрать ноги», а «сделать вход в ноги дешевле» (короткий блок вместо полного отдельного дня).

## 13. Что проверить на устройстве после правок (карта прогона)

1. Программы → PPLUL → фаза «Гипертрофия»: состав дней после R-1…R-4 (проверить, что изменения не задели `phase_id` и не «поехали» по дням).
2. Тренировка → Legs: что день больше не стоит после Pull; кнопка «пропустить» не должна автоскипать ноги при старте Upper (паттерн из §5.1).
3. Тренировка → Upper: presence-проверка «ноги-мини» блока (R-2) и что упражнения не дублируются (DQ-9).
4. Жим лежа: смена политики прогрессии — подсказка о весе должна идти от правила «все подходы ≥ 8 при RPE ≤ 8 → +2.5 кг» (R-5), а не от линейного шага.
5. RPE/RIR: в новом снапшоте тренировки `target_rpe` обязан быть заполнен (DQ-3) — проверить на wk5-тренировке, что поле не null.
6. Разминка: если размине-подходы помечаются, `is_warmup` должен быть true и не входить в приверженность (DQ-5).
7. Подтягивания / собственный вес: тоннаж должен считаться с BW (DQ-6).
8. Замеры: еженедельно вес (утро, 3–7 точек/нед), обхваты раз в 2 недели — грудь/талия/бицепс/бедро/икра; в 12.09 бедро пустое, в 24.08 пустое всё кроме веса.
9. Плечо: при следующем OHP/жиме над головой — боль-чип (pain_event) должен предлагаться; проверить, что событие попадает в `user_injuries`/ограничения, а не только в `pain_events`.

## 14. Приложение: SQL-выгрузки

Пороговая переменная — `user_id = '6416429a-10ef-4e35-ab2f-6c405ee4b283'`, `program_id = '1efe5667-6f9e-4fb1-861b-edb9849c41a5'`.

**A. Структура программы (фазы → дни → упражнения)**

```sql
SELECT ph.phase_number, ph.name AS phase, d.day_number, d.name AS day,
       pe.position, pe.exercise_name, pe.sets, pe.reps_range,
       pe.rest_seconds, pe.intensity, pe.target_rpe, pe.progression_policy
FROM program_days d
JOIN programs p ON p.id = d.program_id
LEFT JOIN program_phases ph ON ph.id = d.phase_id::text AND ph.program_id = p.id
JOIN program_exercises pe ON pe.program_day_id = d.id
WHERE p.id = '1efe5667-6f9e-4fb1-861b-edb9849c41a5'
ORDER BY ph.phase_number, d.day_number, pe.position;
```

**B. Журнал сессий (план/факт/тоннаж/RPE)** — см. запрос в §5: `workouts` (фильтр `started_at IS NOT NULL AND skipped_at IS NULL`) + подзапросы по `workout_exercises`/`workout_logs`.

**C. Показатели по упражнениям**

```sql
WITH ws AS (SELECT w.id, w.name AS day, w.week_number, w.started_at FROM workouts w
            WHERE w.user_id = :uid AND w.program_id = :pid
              AND w.started_at IS NOT NULL AND w.skipped_at IS NULL),
x  AS (SELECT ws.*, e.name AS ex, COALESCE(we.sets, we.target_sets, 0) AS planned, we.target_rpe
       FROM ws JOIN workout_exercises we ON we.workout_id = ws.id
       JOIN exercises e ON e.id = we.exercise_id),
l  AS (SELECT workout_exercise_id,
             count(*) FILTER (WHERE NOT is_warmup) AS done,
             max(weight_kg) FILTER (WHERE NOT is_warmup) AS top_w,
             avg(rpe) FILTER (WHERE NOT is_warmup) AS avg_rpe,
             avg(rir) FILTER (WHERE NOT is_warmup) AS avg_rir
       FROM workout_logs GROUP BY workout_exercise_id)
SELECT x.ex, x.day, count(*) AS sessions, sum(x.planned) AS planned,
       coalesce(sum(l.done),0) AS work_sets,
       round(100.0*coalesce(sum(l.done),0)/nullif(sum(x.planned),0),0) AS adherence_pct,
       round(min(l.top_w),1) AS first_top, round(max(l.top_w),1) AS best_top,
       round(avg(l.avg_rpe),1) AS avg_rpe, max(x.target_rpe) AS target_rpe
FROM x LEFT JOIN l ON l.workout_exercise_id = (
        SELECT id FROM workout_exercises
        WHERE workout_id = x.id AND exercise_id = x.exercise_id LIMIT 1)
GROUP BY x.ex, x.day ORDER BY x.day, x.ex;
```

**D. Недельный объём по мышцам (план vs факт)** — см. запрос `ex`/`dn` с `unnest(e.primary_muscles)`; обязательно фильтровать `started_at IS NOT NULL`, иначе 159 «призрачных» тренировок раздувают плановые цифры (DQ-1).

**E. Замеры тела**

```sql
SELECT metric_date, weight_kg, chest_cm, shoulder_cm, biceps_left_cm, biceps_right_cm,
       forearm_left_cm, forearm_right_cm, waist_cm, abdomen_cm, hips_cm,
       thigh_cm, thigh_left_cm, thigh_right_cm, calf_left_cm, calf_right_cm, neck_cm, notes
FROM body_metrics WHERE user_id = :uid ORDER BY metric_date;
```
