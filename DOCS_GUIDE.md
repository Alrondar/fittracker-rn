# FitTracker — Documentation Guide
Срез: 16.08.2026

Цель: один понятный порядок работы с документацией проекта. Документы не должны конкурировать друг с другом — и не должны конкурировать с кодом.

## Доступ к коду (MCP)

Агент имеет прямой доступ к локальным файлам проекта. Из этого следует разделение ответственности:

- **Код** — источник фактов: какие файлы, функции, RPC, поля и сигнатуры существуют.
- **Документы** — источник решений, правил и intent: почему сделано так, что запрещено, продуктовая модель, blast-radius семантика.

Базовые правила:

1. Факты берутся из кода, а не из документов.
2. При конфликте документа и кода побеждает код. Конфликт исправляется в том же изменении.
3. В документы не вносятся списки файлов/функций/RPC, проверяемые code search'ом. Вместо списка — указатель, где проверять.
4. Один факт имеет одного владельца.

## Source of truth

| Источник | Владелец | Что хранит | Что НЕ хранит |
| --- | --- | --- | --- |
| Код (доступ через MCP) | Фактическое состояние | файлы, схема, RPC, сигнатуры, текущая реализация | решения, правила, статусы задач |
| PRODUCT.md | Product / UX | позиционирование, UX-принципы, ownership Tracker/Engine/Coaching/AI | статусы задач, детали кода |

| INVENTORY.md | Code navigation | роли экранов, семантические зависимости, blast-radius, грабли | полные списки файлов, продуктовые решения |

Не создавать отдельные документы для тех же тем.

## Как читать проект перед изменением

1. **Код через MCP** — найти и прочитать изменяемые файлы и их потребителей. Это шаг ноль: документы не заменяют чтение кода.
2. `PRODUCT.md` — зачем существует feature и каков продуктовый intent.
3. `ROADMAP.md` — входит ли задача в ближайший этап.
4. `STATUS.md` — фактический статус задачи.
5. `INVENTORY.md` — роль экрана, blast-radius, известные грабли.
6. `CLAUDE.md` — архитектурные ограничения.

Только после этого менять код. Если документ говорит одно, а код показывает другое — верить коду и исправить документ в том же изменении.

## Работа без MCP (только Qwen в чате)

Если у агента нет доступа к файлам:

1. Агент **не должен выдумывать содержимое файлов**. Либо запросить текущий файл у пользователя, либо явно пометить предположение.
2. Для поиска кода использовать карту директорий из `INVENTORY.md` (§0 «Navigation») и поисковые шаблоны из того же раздела — их можно дать пользователю для запуска grep/code search.
3. Правила и роли читать из документов: `PRODUCT.md`, `CLAUDE.md`, `INVENTORY.md`, `STATUS.md`, `ROADMAP.md`.
4. Agent workflow и gates — в `AGENTS.md`.

## Работа с MCP

Если подключен filesystem MCP:

1. Код — первичный источник фактов. Перед любым изменением:
   - прочитать файл;
   - найти потребителей code search'ом;
   - проверить RPC в `supabase/migrations/` и `types/database.types.ts`.
2. Документы остаются источником решений и intent; их нужно сверять с кодом.
3. При конфликте документа и кода побеждает код; документ исправляется в том же изменении.
4. Поисковые шаблоны — в `INVENTORY.md` (§0 «Search patterns»).  
5. Правила workflow и обязательные gates — `CLAUDE.md §14` и `AGENTS.md`.

## Document search patterns

- Blast-radius правила: раздел 11 в `INVENTORY.md`.
- Performance правила: раздел 8 в `CLAUDE.md`.
- Performance gate: раздел 8 в `CLAUDE.md`.
- Agent workflow: `AGENTS.md` и раздел 14 в `CLAUDE.md`.
- Дизайн-скилл: разделы 3.1–3.5 в `PRODUCT.md`.
- Status открытых задач: строки с `🔲` в `STATUS.md`.

- Навигация по коду: раздел 0 в `INVENTORY.md`.

## Документная дисциплина

- Новый продуктовый принцип → `PRODUCT.md`.
- Новый этап или изменение приоритетов → `ROADMAP.md`.
- Реализация задачи → `STATUS.md`.
- Новое архитектурное правило → `CLAUDE.md`.
- Новый/изменённый экран, хук или сервис → самого кода и MCP-поиска достаточно; в `INVENTORY.md` фиксируется только *роль*, *грабля* или *blast-radius*, если они неочевидны из кода.
- Не дублировать одну и ту же информацию в нескольких документах.
- Списки файлов/функций/RPC не документируются — документируются указатели, где проверять.
- Drift (документ расходится с кодом) исправляется в том же изменении, где обнаружен.

## Важное изменение от 11.08.2026

Старая формулировка «Не логгер, а тренер» больше не является позиционированием.
Актуальная формулировка:

> FitTracker помогает тебе лучше тренироваться и объясняет свои рекомендации.

AI является опциональным слоем. Базовая ценность должна работать без LLM.
