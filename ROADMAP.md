## 2. Видение: «AI-тренер в кармане»

**Позиционирование rev.3:** не просто логгер, а тренер, который ведёт по периодизации, бережёт от травм, предлагает прогрессию, отвечает на вопросы, замыкает цикл «тренинг + питание + восстановление» и **адаптирует нагрузку под состояние человека**.

**Конкурентное поле:** Hevy/Strong (логирование), Alpha Progression (автопрогрессия), MFP (питание).
**Наш зазор** — безопасность + периодизация + AI-коучинг + **петля обратной связи** в одном app.

### Принципы AI (guardrails — обязательны для всех AI-фич)
- AI = советник, не врач и не судья безопасности. `injury_exercise_warnings` и фарма-дисклеймеры — **ЖЁСТКИЕ ограничения**: AI не может предложить avoid-упражнение, «назначить» фармакологию или отменить противопоказание. Безопасность — таблицы, всё остальное — LLM.
- **Ключи LLM — только серверно** (Supabase Edge Functions). На клиенте ключей нет (правило SEC).
- **Приватность:** в запрос к LLM — минимум PII; фармакология — только абстрактным флагом и только при явном согласии; дисклеймер «AI не заменяет врача».
- **Model-agnostic + Russian-first:** адаптер провайдеров (GPT-4o-mini / Claude Haiku / GigaChat / YandexGPT) — смена без переписывания клиента.
- **Экономика:** маленькие модели для рутины (прогрессия, объяснения), большие — для генерации программ; кэш похожих запросов; лимиты на пользователя/день.
- **Петля качества:** 👍/👎 на каждый AI-ответ + анонимизированный лог консультаций → еженедельное ревью.
- **Данные для решений (rev.3):** AI-тренер должен видеть не только **что сделано**, но и **как перенесено** — readiness, RPE, боль, питание, сон. Без этого AI слеп.

## 3. Приоритизация

**Критерий** = (влияние на retention/активацию) ÷ (трудозатраты). Сначала **данные для AI** (Этап 1-2), затем **AI-фундамент** (Этап 3), затем **умная адаптация** (Этап 3.5), затем крупные AI-ставки. Социалку — только после здоровых D7/D30.

## 5. Технический трек (параллельно фичам)

- Новые RPC — только `supabase/migrations` + ревью (правила PROMPTS.md); после миграций регенерация типов (`--db-url` + utf8)
- Не добавлять хардкод цветов/конфигов; новые фичи — через сервисы + React Query (правила CLAUDE.md)
- Файлы > 450 строк — сначала разбиение (SCALE-5)
- CI-минимум на PR: `tsc --noEmit` + `jest` (после 0.4)

### AI-инфраструктура (Этап 3):
- миграция: `create extension vector; alter table exercises add column embedding vector(1024);` + one-off эмбеддинг-пайплайн
- RPC `match_exercises_semantic(query_embedding, ...)` — SECURITY INVOKER + STABLE (по правилам PROMPTS.md)
- таблица `ai_consultations` (user_id, feature, feedback, created_at) + RLS `auth.uid() = user_id` (добавить в список RLS CLAUDE.md при создании)
- deploy: `supabase functions deploy llm-proxy`; секреты провайдеров — `supabase secrets set`

### Данные для AI (Этапы 1-2, rev.3):
- миграции: `daily_readiness`, `pain_events`, `assessments`, `ai_recommendations` + RLS `auth.uid() = user_id` (добавить в список RLS CLAUDE.md)
- RPC `get_weekly_summary(user_id, week_start)` — SECURITY INVOKER + STABLE (агрегация readiness, RPE, pain, nutrition, volume)
- индексы: `daily_readiness(user_id, date)`, `pain_events(user_id, occurred_at)`, `workout_logs(rpe, created_at)`
- миграция `workout_logs`: `ALTER TABLE workout_logs ADD COLUMN rpe smallint, rir smallint, difficulty text`
